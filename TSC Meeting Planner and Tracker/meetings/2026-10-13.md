## 4. CoSAI Week in Review

> A summary of what was discussed across CoSAI Workstreams and SIGs
> since the last TSC meeting. Sourced from meeting minutes files dated
> within the last 14 days. Groups that did not meet are noted explicitly.

| Group | Last Met | Summary |
|---|---|---|
| WS1 — Software Supply Chain Security for AI Systems | Did not meet | Did not meet |
| WS2 — Preparing Defenders for a Changing Cybersecurity Landscape | 2026-10-06 | Reviewed CoSAI's recent zero trust for AI publication and the status of the telemetry workstream nearing completion. The group discussed two proposed Duke University student collaboration projects — an OWL/RDF knowledge graph of the CoSAI risk map surfaced via an MCP service, and a testing harness to validate CoSAI-RM control effectiveness — both pending a TSC consensus call. An Apache-style incubation model was proposed for prototype projects. Backlog items including machine unlearning and differential privacy were identified for the telemetry security and privacy follow-on phase. TSC relevance: Duke projects pending TSC approval; NIST AI RMF for critical infrastructure collaboration needs CoSAI telemetry input. |
| Telemetry SIG — AI Security Telemetry (WS2) | 2026-10-08 | Reviewed the telemetry document now at version 0.6 on the main branch, restructured into three YAML-driven parts with a risk map explorer interface. The group aligned to complete sanity checks and submit the document to the TSC by Tuesday (this meeting). Future work will pivot to the security and privacy of telemetry, including cryptographic hash chaining. TSC relevance: Josiah Hagen's action item is to submit the v0.6 document for TSC review at this meeting (tracked in #72). |
| WS3 — AI Security Risk Governance | 2026-10-01 | Zeal Somani presented a simplified tabular version of the AI Shared Responsibility Framework (version 2), mapping five AI consumption models (SaaS, PaaS, Agent PaaS, BYOM, IaaS) against CoSAI-RM control layers and personas. The group aims to publish version 2 before year-end, with stakeholder sessions planned for November including representatives from OpenAI, Google, and Anthropic. Publication format (PDF vs. GitHub landing page) remains under discussion. No direct TSC decisions required at this time. |
| WS3 Threat Modeling — Agentic Coding Threat Modeling (WS3) | 2026-10-02 | Kevin Calloway reported on discussions with the agentic coding group and WS3, where David recommended scheduling a leadership meeting to decide between a broad ADLC threat model approach or a focused red-teaming/pen-testing security controls approach. Approximately 18 review comments from Navneet remain on the current threat model document, requiring a collaborative working session. Julia Cabral and Shrey Bagga agreed to review the document. TSC relevance: Kevin Calloway was to contact Claudia to schedule the direction-setting leadership meeting with TSC co-chair involvement. |
| CoSAI-RM SIG — Coalition for Secure AI Risk Map | 2026-10-07 | Reviewed and approved the informed agent consent surface control and associated consent fatigue risk under the new description-versus-guidance format. Discussed the secrets and key management control, including challenges around agent direct access to cryptographic keys and key sharding. Infrastructure updates included npm/node dependency upgrades, establishment of separate semantic versioning policies for tooling and content, and integration of new framework mappings (ETSI, EU AI RMF). TSC relevance: David LaBianca and J.R. Rao have an action item to co-author a blog post on consent fatigue risks in agentic systems. |
| Code SIG — Security of AI-Assisted Code Generation | 2026-10-06 | Released CodeGuard version 1.5, focused on scaffolding around code guard rules. The group discussed documenting a semantic versioning strategy for CodeGuard content and format (aligned with MITRE Atlas practices). Shrey Bagga's local model evaluation PR (issue 73) showed CodeGuard triggering successfully in five of six test cases. Vinay Bansal proposed expanding CodeGuard across all AI SDLC phases using MCP capabilities as a unified security context depot. No direct TSC action required. |
| WS4 — Secure Design Patterns for Agentic Systems | 2026-10-08 | Reviewed RSA Conference submission deadlines (due midnight Pacific the following day) and confirmed that all working group sessions must be scheduled through OASIS for compliance and CLA records. Shriti Priya presented the Multimodal Agentic Security taxonomy — a modality-agnostic complementary layer to STRIDE, MITRE ATLAS, and NIST AI, covering boundary trust, representation disguises, and system processing stages. The group plans to publish a white paper and explore a portable skill/code set. TSC relevance: the Multimodal Threat Taxonomy is an active roadmap deliverable (#10). |
| ADLC SIG — Security of Agent Development Lifecycle | 2026-10-07 | Resolved RFC 214 on agent decommissioning and maintenance, deferring CMMI maturity levels to a later release and framing decommissioning as an SLA availability question. Deferred agent behavioral monitoring (PR 220) to the telemetry workstream. Assigned sections of ADLC definitional paper PR 197 to contributors with an October 21 initial draft deadline. Mandar Gaonkar (new contributor) proposed adding post-development agent registration to section 3.5. TSC relevance: ADLC Lifecycle Definitional Paper is a tracked roadmap deliverable (#12); October 21 draft deadline approaching. |
| Agent Credentials Group | 2026-10-08 | Reviewed the restructured agent credentials document (~80% complete), now organized around four core areas: identity, ownership, composition, and capabilities/skills. Agreed on a target document length of approximately 20 pages and GitHub markdown as the canonical format. Removed Appendix E (layered identifier examples). Ongoing debate about whether software build artifacts and hashes constitute credentials or evidence was deferred to a follow-up session. TSC relevance: Agent Credentials Paper is a tracked roadmap deliverable (#9) with an October 31 target. |
| Multimodal Agentic Security — Multimodal Threat Taxonomy (WS4) | 2026-10-12 | Discussed real-world adoption of the taxonomy: Navneet Keshav presented Lenovo's three-gate agentic threat modeling workflow as a candidate case study for the white paper. The group aligned on publishing the taxonomy as a CoSAI white paper before contributing individual techniques to MITRE ATLAS. Victor Lu advised using OWASP for novel attack references and MITRE ATLAS for standardized terminology to avoid naming conflicts. Shriti Priya will raise a pull request once the markdown is cleaned up. Cross-modal scenarios inclusion was deferred pending further feedback. |
