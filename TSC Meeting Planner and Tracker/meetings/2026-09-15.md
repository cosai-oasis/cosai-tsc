## 4. CoSAI Week in Review

> A summary of what was discussed across CoSAI Workstreams and SIGs
> since the last TSC meeting. Sourced from meeting minutes files dated
> within the last 14 days. Groups that did not meet are noted explicitly.

| Group | Last Met | Summary |
|---|---|---|
| WS1 — Software Supply Chain Security for AI Systems | Did not meet | Did not meet |
| WS2 — Preparing Defenders for a Changing Cybersecurity Landscape | Did not meet | Did not meet |
| WS3 — AI Security Risk Governance | 2026-09-03 | The group addressed documentation gaps around the CoSAI Risk Management framework and agreed to absorb the Shared Responsibility Framework (SRF) directly into WS3 without a separate SIG. Karttik Panda will draft a simplified 2-page SRF mapped to the CoSAI-RM, targeting an October 1 first draft; separate SRF SIG meetings were cancelled and the main WS3 meeting extended by 30 minutes. New contributor Ross Webster-Salter (Mercedes-Benz) joined. TSC relevance: Karttik Panda noted the need to bring a consolidated WS3 vision and roadmap to a future TSC meeting, and the SRF simplification/CoSAI-RM mapping is a deliverable the TSC tracks. |
| WS4 — Secure Design Patterns for Agentic Systems | 2026-09-10 | WS4 received an overview of the ODIS agentic authorization framework (passport, bridge, router layers) following an on-site meeting at NVIDIA HQ. Volunteers were assigned to specification components: Andrii Deinega (bridge), Teryl/IBM (router), Rithikha Rajamohan (passport). Ian Molloy introduced Issue 178 and ten sub-issues to reconcile white paper risks and controls into the YAML-based CoSAI-RM; Laura Seletos will present a proposal on standardized patterns at the next WS4 meeting. TSC relevance: ADLC SIG co-chair nominations (Courtenay Ngo, Matthew Gladney) are pending TSC confirmation; the RM reconciliation work in Issue 178 is cross-cutting. |
| CoSAI-RM SIG — Coalition for Secure AI Risk Map | 2026-09-09 | The SIG reviewed and began refactoring proposed risk issues 24–27 (including agent memory poisoning and deceptive agent reporting). The group confirmed a V1 release tag tied to the upcoming MCP paper and current develop-branch changes. Component work included defining consent surfaces, isolation runtime, audit record repository, and renaming "tool server" to "tool service." TSC relevance: V1 tagging aligns with MCP decomposition milestone the TSC tracks; bot-generated comments on Issue 525 were flagged as an ongoing concern. |
| Code SIG — Security of AI-Assisted Code Generation | 2026-09-08 | The SIG deployed a merged evaluation harness (Inspect AI + Semgrep containers) and ran baseline tests comparing standard, secure-phrased, and CodeGuard-enabled outputs, finding CodeGuard and security phrasing currently perform similarly. The team decided to shift CodeGuard from rules toward procedural agent skills and deprecated legacy rule-based approaches. Plans include mutation studies on agent structures, benchmarking local models against frontier models, and collaborating on a blog post documenting the security harness build process. Meeting cadence is shifting to 30-minute weekly sessions. |
| ADLC SIG — Security of Agent Development Lifecycle | 2026-09-09 | The SIG focused on drafting the ADLC definitional paper, with Courtenay Ngo volunteering as lead author. Decommissioning was formally adopted as a lifecycle stage (drawing on NIST 853), and the observability RFC was reframed to align with WS2 telemetry and MCP controls. The group is transitioning documentation from Google Docs to GitHub for durable governance records. TSC relevance: Courtenay Ngo and Matthew Gladney were nominated as new ADLC SIG co-chairs pending TSC confirmation; J.R. Rao was asked to review and approve PR #183 for the agenda. |
| Agent Credentials Group | 2026-09-10 | The group held a working session reviewing paper draft sections using a new traffic light readiness scoring system. Discussion focused on Otus credential architecture and whether Otus Agent Runtime Credentials constitute an implementation of the group's broader agent credential definition. The group debated classification of registration records and proposed two credential categories: "Claim Credentials" (claims signed by a trusted party) and "Evidence-based Credentials" (results of appraisal processes); final taxonomy adoption was deferred for further revision. TSC relevance: overlap between the Otus passport layer and agent credentials work was noted; coordination with the WS4 ODIS volunteer assignments is ongoing. |
