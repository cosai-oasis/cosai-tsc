## 4. CoSAI Week in Review

> A summary of what was discussed across CoSAI Workstreams and SIGs
> since the last TSC meeting. Sourced from meeting minutes files dated
> within the last 14 days. Groups that did not meet are noted explicitly.

| Group | Last Met | Summary |
|---|---|---|
| WS1 — Software Supply Chain Security for AI Systems | 2026-08-26 | The group focused on scoping transportable evidence for AI supply chains, adopting GitHub Issue 31 as the central location for scenario brainstorming. A regulated banking use case was proposed as the initial bounded example. The group agreed that standards mapping would be delegated to WS3, and data sovereignty was established as a required constraint. Key next steps include posting persona-based scenarios and coordinating with Imran on agent trust integration. |
| WS2 — Preparing Defenders for a Changing Cybersecurity Landscape | Did not meet | Did not meet |
| WS3 — AI Security Risk Governance | 2026-09-03 | Karttik Panda, newly joining the TSC, raised concerns about insufficient documentation of the CoSAI Risk Management framework's development status and requested a 6–8 month roadmap. The group agreed to absorb the Shared Responsibility Framework directly into WS3 (no separate SIG), with Karttik leading simplification to a 2-page version targeting an October 1 first draft. Separate SRF SIG meetings will be cancelled and the main WS3 call extended by 30 minutes. A new contributor from Mercedes-Benz was welcomed. TSC relevance: Karttik plans to bring a consolidated WS3 vision to a future TSC meeting. |
| WS4 — Secure Design Patterns for Agentic Systems | 2026-09-03 | The group reviewed MCP v1 risks and controls decomposition, with reviewers instructed to map against v1 before proposing v2 additions. New TSC co-chairs were announced. The Agent Credentials paper targets an October draft; the multimodal threat taxonomy targets late October. Jeff Leva volunteered to lead the containment follow-up paper. The ADLC SIG reported a leadership vacancy and needs for additional co-chairs. Josiah Hagen presented the Telemetry for AI Systems roadmap, requesting feedback via GitHub by September 14. TSC relevance: deliverable timelines to be firmed up at this Tuesday's meeting; ADLC leadership gap escalated. |
| CoSAI-RM SIG — Coalition for Secure AI Risk Map | 2026-08-26 | The SIG worked through pull request workflows, merging PR 473 into the develop branch to facilitate WS4 risk and control reviews. PR 497 scope was reduced to avoid blocking progress, with secondary improvements deferred to a follow-up issue. CI updates were introduced requiring every agent and skill to ship with evaluations. Approximately 8,000 lines of unused control and risk graph generation code were deprecated and removed. TSC relevance: MCP-paper-driven risks and controls are being broken into domain-specific issues for WS4 review. |
| Code SIG — Security of AI-Assisted Code Generation | 2026-08-25 | The SIG reviewed Code Guard modernization priorities, focusing on reducing context window usage and updating the outdated folder-based rule structure. Agent Package Manager support was scoped as optional rather than a standard pathway. A new two-container security evaluation harness was implemented for benchmarking, with plans to expand testing to local open-source models. Meeting cadence changes were deferred pending September attendance data. |
| ADLC SIG — Security of Agent Development Lifecycle | 2026-08-26 | The group debated decommissioning RFC scope, agreeing to simplify to hard decommissioning only. Observability was reclassified as a top-level category rather than a lifecycle stage. David LaBianca raised process concerns about the absence of foundational papers defining ADLC goals and outputs, and the group aligned on pausing RFC filings to re-evaluate P0 priorities with leadership (Ian and Sarah). TSC relevance: leadership gap confirmed; sandboxing was flagged as a potential P0 priority; group needs TSC guidance on strategic direction. |
| Agent Credentials Group | 2026-09-03 | The group worked on clarifying agent credential definitions, aligning on RATS terminology (attestors generate evidence; verifiers produce attestation results), and discussing sub-agent identity scalability concerns. CPEX is rebranding to "access policy engine." An ODIS epic was created to document CPEX-to-ODIS implementation gaps. The group is collaborating with Red Hat on an agent passport and tamper-evident logging integration. Agent Manifests scope remains under discussion pending a meeting with Imran. |
