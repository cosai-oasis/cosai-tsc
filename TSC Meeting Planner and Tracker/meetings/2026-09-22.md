## 4. CoSAI Week in Review

> A summary of what was discussed across CoSAI Workstreams and SIGs
> since the last TSC meeting. Sourced from meeting minutes files dated
> within the last 14 days. Groups that did not meet are noted explicitly.

| Group | Last Met | Summary |
|---|---|---|
| WS1 — Software Supply Chain Security for AI Systems | Did not meet | Did not meet |
| WS2 — Preparing Defenders for a Changing Cybersecurity Landscape | Did not meet | Did not meet |
| WS3 — AI Security Risk Governance | Did not meet | Did not meet |
| WS4 — Secure Design Patterns for Agentic Systems | 2026-09-17 | The group discussed a proposal from Laura Seletos (NVIDIA) for a standardized, vendor-agnostic security patterns framework providing prescriptive guidance, threat models, and architectural diagrams for AI workloads, intended to evolve into deployable infrastructure-as-code assets. Working group updates included: the containment paper advancing rapidly with multiple pull requests submitted; ODIS aligned on a three-layer architecture (bridge, passport, router) with specification work to proceed asynchronously via GitHub issues; the multimodal taxonomy group meeting weekly; and the agent credentials working group targeting a first rough draft. Ian Molloy raised concerns about cross-deliverable internal consistency and the challenge of securing volunteers for risk mapping. |
| CoSAI-RM SIG — Coalition for Secure AI Risk Map | 2026-09-09 | The SIG focused on refactoring proposed risk issues 24–27 (including agent memory poisoning and deceptive agent reporting), discussed component architecture updates (consent surfaces, isolation runtime, tool service rename), and confirmed that the upcoming MCP paper release plus current develop-branch changes will constitute the CoSAI-RM V1 tag. Bot-generated comments on GitHub issues were noted as a concern. The SIG also discussed longer-term goals including EU parliamentary engagement, SMB risk metrology tooling, and roundtables planned for September–October. |
| Code SIG — Security of AI-Assisted Code Generation | 2026-09-15 | The SIG reviewed a security fix for the MCP server Docker configuration, discussed modernizing the Code Guard skill structure from retrofitted rules to procedural-guidance-first design, and ran benchmarks using Inspect AI with a Notre Dame benchmark. The group agreed to initially publish final benchmark results (with token usage and cost metrics) and to consult the TSC before publishing full model traces — a direct TSC-relevant request. The group also agreed that Code Guard metadata scope should remain restricted to the skill itself. |
| ADLC SIG — Security of Agent Development Lifecycle | 2026-09-16 | New SIG leads Courtenay Ngo and Matthew were introduced following Parul's departure. The group discussed a definitional paper (PR 197) distinguishing ADLC from SDLC, with a two-week review deadline, and agreed to incorporate the legacy scope document into it. The decommissioning lifecycle RFC 170 is being cleaned up for review; the group confirmed decommissioning must be a distinct lifecycle stage requiring material mapping across the risk model before acceptance. RFC 175 on observability was closed as redundant. The group also flagged agent failure mode monitoring as a topic needing further development. |
| Agent Credentials Group | 2026-09-10 | The group held a working session to review paper drafts and introduced a traffic light readiness scoring system for sections. Discussion centered on the relationship between Otus Agent Runtime Credentials and the group's broader agent credential definitions, including whether runtime credentials constitute agent credentials or evidence. The group proposed classifying credentials into "Claim Credentials" (claims signed by a trusted party) and "Evidence-based Credentials" (results of appraisal processes), with final taxonomy adoption deferred for further revision. |
