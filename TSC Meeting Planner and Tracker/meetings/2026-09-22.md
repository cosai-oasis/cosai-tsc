## 4. CoSAI Week in Review

> A summary of what was discussed across CoSAI Workstreams and SIGs
> since the last TSC meeting. Sourced from meeting minutes files dated
> within the last 14 days. Groups that did not meet are noted explicitly.

| Group | Last Met | Summary |
|---|---|---|
| WS1 — Software Supply Chain Security for AI Systems | Did not meet | Did not meet |
| WS2 — Preparing Defenders for a Changing Cybersecurity Landscape | Did not meet | Did not meet |
| WS3 — AI Security Risk Governance | Did not meet | Did not meet |
| WS4 — Secure Design Patterns for Agentic Systems | 2026-09-10 | The group covered administrative updates including new TSC co-chair announcements and confirmation that Courtenay Ngo and Matthew Gladney were proposed as ADLC SIG leads pending TSC approval. Matthew Gladney and Nir Paz presented a detailed overview of the ODIS agentic authorization framework — a three-layer architecture (passport, bridge, router) recently reviewed at an NVIDIA on-site with ~40 participants — with volunteers assigned to each layer. Ian Molloy introduced Issue 178 and ten sub-issues for reconciling white paper risks into the CoSAI-RM YAML framework, with Laura Seletos announcing a proposal on standard patterns and automation processes for the following week. The containment follow-on paper skeleton is underway with Jeff Leva as lead editor and a three-week contribution window. |
| CoSAI-RM SIG — Coalition for Secure AI Risk Map | 2026-09-09 | The SIG worked through risk issue refactoring, discussing issues 24–27 (agent memory poisoning, deceptive agent reporting, implicit cross-boundary trust, and capability decomposition). The team confirmed a V1 tag aligned with the upcoming MCP paper release. New components — agent consent surface, application consent surface, isolation runtime, and component tool service — were reviewed, with "tool server" renamed to "tool service." Bot-generated comments were identified on issue 525 (Deceptive Agent Reporting), flagging the need for contributor accountability measures. Upcoming EU parliamentary engagement and stakeholder roundtables were noted as external use cases for the Risk Model. |
| Code SIG — Security of AI-Assisted Code Generation | 2026-09-08 | The SIG reviewed CodeGuard modernization, shifting from rule-based approaches to procedural agent skill definitions to improve activation reliability and usability. The evaluation harness (using Inspect AI, Semgrep, and an orchestration container) was merged and documented; baseline testing with Codex showed 4–5 hour run times and similar performance between CodeGuard and plain security phrasing, motivating further improvement. The group agreed to collaborate on a blog post documenting the security harness build process, and transitioned to a 30-minute weekly meeting format. Local model benchmarking against frontier models is a planned next step. |
| ADLC SIG — Security of Agent Development Lifecycle | 2026-09-09 | Sarah Novotny announced the nomination of Courtenay Ngo and Matthew as new SIG co-chairs, with TSC confirmation expected imminently. The group prioritized the ADLC definitional paper as P0, with Courtenay Ngo volunteering to lead the drafting effort using existing prior art. Decommissioning was formally adopted as a lifecycle stage, drawing on NIST 853 controls. The group is transitioning from Google Docs and Slack to GitHub as the durable record of governance work. Cross-workstream alignment with WS2 telemetry and MCP controls was noted by Emer. |
| Agent Credentials Group | 2026-09-10 | The group held a collaborative working session to review draft sections of the agent credentials paper using a new traffic light readiness system (red = needs attention, green = ready for broader WS4 review). Discussion centered on aligning with the Otus framework's three-layer architecture and debating whether Otus runtime credentials constitute agent credentials under the group's definition. The key conceptual outcome was a proposed credential typology: "Claim Credentials" (signed by a trusted party) and "Evidence-based Credentials" (results of an appraisal process); final adoption was deferred for further revision. |
