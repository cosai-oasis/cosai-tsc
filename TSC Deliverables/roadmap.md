## 🔵 Approval Pipeline Stages

Deliverables move through these stages in order:

| Stage | Meaning |
|---|---|
| 🔵 Planned | Agreed at TSC level; work not yet started |
| 🔵 In Progress | Actively being worked on by the responsible workstream or SIG |
| 🟡 TSC Co-chairs Review | Draft submitted; under review by TSC co-chairs |
| 🟠 TSC Review | Under review by full TSC membership |
| 🔴 TSC & PGB Review | Under joint review by TSC and PGB |
| 🟣 TSC Full Majority Vote | Formal TSC full majority vote in progress |
| 🟤 TSC & PGB Full Majority Vote | Formal joint TSC and PGB full majority vote in progress |
| 🗳️ TSC Vote | Active TSC election or appointment vote in progress |
| 🟢 Published / Complete | Finished, published, or appointment confirmed |

## 📌 How to Update This File

1. After each TSC meeting, update the **Current Stage** and **Next Deadline**
   for any deliverable that progressed
2. When a new deliverable is proposed by a TSC member, they open a GitHub
   Issue labeled `proposed-deliverable` — it appears in the Proposed
   Deliverables table above for discussion at the next TSC meeting
3. When a proposed deliverable is accepted by the TSC, move it to the
   Active Deliverables table and update its stage
4. When a deliverable is complete, move it to 🟢 Published / Complete
   and add a link to the published work in the Issue before closing it
5. Commit and push the updated roadmap:
   ```
   git add .
   git commit -m "roadmap: update deliverables status"
   git push
   ```
